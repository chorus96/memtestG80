# CUDA 세미나 커리큘럼 — `memtestG80`로 배우는 실전 GPU 프로그래밍

> **대상**: C 언어는 알지만 CUDA는 처음인 입문자
> **교재**: 이 저장소(`memtestG80`)의 실제 소스 코드
> **형식**: 다회차 시리즈 (세션 0 ~ 세션 5, 회차당 90~120분)
> **언어 표기**: 한글 용어 옆에 원어(영어)를 병기합니다. 예) 커널(kernel)

---

## 0. 이 세미나의 설계 철학

대부분의 CUDA 입문 강의는 `vectorAdd` 같은 장난감 예제로 시작해서 실무 코드로 넘어갈 때 벽에 부딪힙니다.
이 세미나는 **처음부터 실제로 동작하는 프로덕션 CUDA 코드**(`memtestG80`)를 교재로 삼습니다.

`memtestG80`가 입문 교재로 뛰어난 이유:

1. **주제가 명확하다** — "GPU 메모리에 값을 쓰고, 다시 읽어서, 같은지 비교한다." 이 한 문장이 전부입니다.
   알고리즘이 단순하므로 학습자는 CUDA 문법과 병렬 패턴 자체에 집중할 수 있습니다.
2. **교과서적 병렬 패턴이 실코드에 있다**:
   - **스레드 인터리빙 + 메모리 병합(coalescing)** — `THREAD_ADDRESS` 매크로 한 줄에 응축
   - **공유 메모리 트리 리덕션** — `deviceVerifyConstant`는 CUDA 리덕션의 교과서적 예시
   - **`__popc` 하드웨어 인트린식** — 틀린 비트 개수를 세는 우아한 오류 집계
   - 이 세 가지는 다른 입문 교재에서 좀처럼 실코드로 보기 어렵습니다.
3. **실무 요소가 들어 있다** — RAII 자원 관리(`memtestState`), 3계층 API 설계, 비동기 커널과 타이밍,
   오류 센티넬 관례, 라이브러리로의 임베드까지.
4. **하드웨어를 직접 만진다** — 추상적인 계산이 아니라 실제 GPU 메모리의 물리적 오류를 찾는 코드입니다.
   결과가 눈에 보이므로 동기 부여가 강합니다.

## 1. 코드베이스 지도 (강사용 참고)

| 파일 | 역할 | 세미나에서 다루는 회차 |

| `memtestG80_core.cu` | **핵심** — 모든 커널·호스트 함수·병렬 리덕션·대역폭 측정 | 세션 1~4 |
| `memtestG80_cli.cu` | `main()` — 13종 테스트를 순차 실행하는 프런트엔드(임베드 예제) | 세션 0, 4, 5 |
| `ezOptionParser.hpp` | 헤더 전용 명령행 인자 파서 (보조) | 세션 5 (캡스톤 C) |
| `Makefiles/` | OS별 빌드 설정 (linux32/64, osx, windows) | 세션 0 |

### 세미나에서 반복해서 돌아올 "황금 코드 3형제"

```
THREAD_ADDRESS 매크로     (core.cu:26)   — 스레드가 자기 word 주소를 계산 (모든 테스트의 심장)
deviceWriteConstant       (core.cu:189)  — 패턴을 메모리에 쓴다 (가장 단순한 커널)
deviceVerifyConstant      (core.cu:213)  — 되읽어 __popc로 오류를 세고, 트리 리덕션으로 합산
```

이 셋은 짧으면서도 CUDA의 핵심 개념(스레드 인덱싱, 전역/공유 메모리, 병렬 리덕션)을 모두 담고 있어
**전 회차의 중심 예제**로 사용합니다.

### `memtestG80` vs `cuda_memtest` — 왜 이 도구인가
같은 계열의 `cuda_memtest`는 블록당 스레드 1개(`<<<grid,1>>>`)의 의도적으로 단순한 커널로 CUDA **문법 입문**에
좋습니다. 반면 `memtestG80`은 **블록당 512 스레드 + 공유 메모리 리덕션 + coalescing**을 실제로 구현해,
CUDA의 **병렬 패턴**을 실코드로 배우기에 더 적합합니다. 본 커리큘럼은 이 강점(세션 1의 매핑, 세션 3의 리덕션)에
초점을 맞춥니다.

## 2. 전체 시리즈 로드맵

```
세션 0  환경 구축 & 큰 그림          →  Makefile로 빌드·실행해서 "GPU가 일한다"를 눈으로 확인
세션 1  스레드 모델 & 주소 매핑       →  THREAD_ADDRESS와 메모리 병합(coalescing) 완전 정복
세션 2  메모리 모델 & 쓰기·검증       →  전역 메모리, write→verify 패턴, Moving Inversions
세션 3  공유 메모리 & 병렬 리덕션 ★   →  __popc, 트리 리덕션, __syncthreads (이 도구의 백미)
세션 4  테스트 알고리즘 & 성능        →  13종 테스트 카탈로그, 패턴 생성, D2D 대역폭 측정
세션 5  객체지향 API · 라이브러리 · 캡스톤 → memtestState, RAII, 임베드, 나만의 테스트
```

각 세션은 **[개념 강의(슬라이드)] → [코드 리딩(실제 파일)] → [실습 랩(직접 수정·실행)]** 3단 구성입니다.

## 세션 0 — 환경 구축과 큰 그림 (90분)

**학습 목표**
- GPU가 CPU와 무엇이 다른지(처리량 vs 지연시간) 한 문장으로 설명할 수 있다.
- `memtestG80`를 직접 빌드하고 실행할 수 있다.
- 이 도구가 무엇을 하는 프로그램인지(하드/소프트 오류 검사) 설명할 수 있다.

**강의 내용**
1. GPU 컴퓨팅이란: SIMT(Single Instruction, Multiple Threads), 수천 코어의 의미
2. 호스트(host, CPU) ↔ 디바이스(device, GPU)의 분업
3. `memtestG80`가 푸는 문제: GPU 메모리의 하드 오류·소프트 오류, ECC 부재
4. 빌드 시스템: OS별 `Makefile`, `nvcc`, `-Xptxas -v`

**코드 리딩**: `README.md`의 빌드 절차, `Makefiles/Makefile.linux64`, `main()`(`cli.cu:73`)

**실습 랩 (Lab 0)**: [`세션0_실습랩.md`](세션0_실습랩.md) — 빌드, 기본 실행, `nvidia-smi` 관찰, 인자 실험

## 세션 1 — CUDA 스레드 모델과 주소 매핑 (120분) ★ 핵심 회차

**학습 목표**
- `__global__` 커널이 일반 C 함수와 무엇이 다른지 설명할 수 있다.
- `<<<1024, 512>>>` 실행 구성의 의미를 안다.
- `blockIdx`·`threadIdx`·`blockDim`으로 스레드가 자기 데이터를 찾는 원리를 안다.
- `THREAD_ADDRESS` 매크로를 네 항으로 나눠 설명하고, 메모리 병합(coalescing)과의 관계를 안다.

**강의 내용**
1. 커널(kernel)과 `__global__`/`__device__`/`__host__`
2. 실행 계층: Grid → Block → Thread (1024 × 512 = 524,288 스레드)
3. 내장 변수: `blockIdx.x`, `threadIdx.x`, `blockDim.x`, `gridDim.x`
4. **★ `THREAD_ADDRESS` 해부** (`core.cu:26`) — base + 블록 오프셋 + 반복 오프셋 + 스레드 오프셋
5. 인터리빙과 메모리 병합: 왜 이웃 스레드가 이웃 주소를 맡나

**코드 리딩**: `THREAD_ADDRESS`(`core.cu:26`), `deviceWriteConstant`(`core.cu:189`), `gpuWriteConstant`(`core.cu:185`)

**실습 랩 (Lab 1)**: [`세션1_실습랩.md`](세션1_실습랩.md) — 스레드 인덱스 출력, 블록 구역 계산, coalescing 깨보기

## 세션 2 — 메모리 모델과 쓰기·검증 패턴 (120분)

**학습 목표**
- 전역(global)/공유(shared)/레지스터(register) 메모리를 구분한다.
- 왜 "쓰기 커널 종료 → 읽기 커널 시작" 패턴이 필요한지(메모리 반영) 설명할 수 있다.
- Moving Inversions 알고리즘을 이해한다.

**강의 내용**
1. GPU 메모리 계층 개요
2. 할당·전송 API: `cudaMalloc`/`cudaMemcpy`/`cudaFree`, `memtestState::allocate`(`core.cu:51`)
3. 쓰기→검증 뼈대: `gpuWriteConstant` → `SOFTWAIT` → `gpuVerifyConstant`
4. `SOFTWAIT` 매크로(`core.h:49`): 비동기 커널 완료 기다리기, 타임아웃
5. Moving Inversions(`core.cu:370`): 패턴과 보수를 번갈아 쓰기

**코드 리딩**: `allocate`(`core.cu:51`), `gpuMovingInversionsOnesZeros`(`core.cu:370`), `SOFTWAIT`(`core.h:40`)

**실습 랩 (Lab 2)**: [`세션2_실습랩.md`](세션2_실습랩.md) — 패턴 변경, 오류 인위 주입, CPU 버전 대조, N↔MB 관계

## 세션 3 — 공유 메모리와 병렬 리덕션 (120분) ★ 백미

**학습 목표**
- `extern __shared__`로 블록 내 협업 버퍼를 만들 수 있다.
- `__popc`/`BITSDIFF`가 틀린 비트 개수를 세는 원리를 안다.
- 트리 리덕션(stride 반씩 줄이기)을 한 줄씩 설명할 수 있다.
- `__syncthreads`가 없으면 왜 결과가 비결정적인지 안다.

**강의 내용**
1. 문제: 52만 개 부분합을 어떻게 합치나 (전역 원자연산의 비용)
2. 3단계 해법: 블록 내 트리 합산 → 블록당 1개 저장 → 호스트 최종 합
3. `__popc`/`BITSDIFF`(`core.cu:28`): XOR 후 1비트 개수
4. **★ `deviceVerifyConstant` 완독**(`core.cu:213`): 공유 배열 초기화 → 부분합 → 트리 리덕션 → 대표 저장
5. `__syncthreads`(`core.cu:228`)의 필요성: 배리어와 경쟁 조건
6. 공유 메모리 재활용: LCG shmem(`core.cu:346`), random blocks 병렬 생성(`core.cu:723`)

**코드 리딩**: `deviceVerifyConstant`(`core.cu:213`), `BITSDIFF`(`core.cu:28`), `gpuVerifyConstant`(`core.cu:195`)

**실습 랩 (Lab 3)**: [`세션3_실습랩.md`](세션3_실습랩.md) — `__syncthreads` 빼보기, `__popc` 확인, 블록 합 관찰, shmem 크기 실험

## 세션 4 — 테스트 알고리즘과 성능 측정 (120분)

**학습 목표**
- 13종 테스트가 각각 어떤 결함을 노리는지 개관한다.
- Walking bits·Modulo가 비트 연산으로 패턴을 만드는 법을 안다.
- Logic(LCG) 테스트가 메모리가 아니라 연산 로직을 검사함을 이해한다.
- D2D `cudaMemcpy`로 대역폭을 재는 법과 비동기 함정을 안다.

**강의 내용**
1. 테스트 카탈로그: Memtest86 계보와 13종 실행 순서(`cli.cu:185`)
2. 패턴 생성: Walking 8/32-bit(`core.cu:392`, `579`), Modulo-20(`core.cu:802`)
3. Random Blocks(`core.cu:626`, `723`): 재현 가능한 난수
4. Logic/LCG(`core.cu:298`, `324`): 짝 XOR, 0으로 복귀, shmem 변형
5. 대역폭 측정(`core.cu:168`): D2D memcpy, `cudaThreadSynchronize`, ×2

**코드 리딩**: 메인 루프(`cli.cu:185`), `gpuWalking8BitM86`(`core.cu:392`), `deviceShortLCG0`(`core.cu:324`), `gpuMemoryBandwidth`(`core.cu:168`)

**실습 랩 (Lab 4)**: [`세션4_실습랩.md`](세션4_실습랩.md) — 테스트별 프로파일, Walking 패턴 손계산, LCG 0 확인, 대역폭 함정

## 세션 5 — 객체지향 API · 라이브러리 · 캡스톤 (120분)

**학습 목표**
- 3계층 API(클래스/호스트/커널)의 역할 분담을 이해한다.
- RAII로 GPU 자원이 자동 관리되는 원리를 안다.
- `memtestState`를 내 프로그램에 라이브러리로 임베드한다.
- 배운 것을 종합해 나만의 테스트를 만든다.

**강의 내용**
1. 3계층 설계: `memtestState` → `__host__ gpuXxx` → `__global__ deviceXxx`
2. RAII: 생성자/소멸자(`core.h:78`), `allocate`의 예외 안전(`core.cu:51`)
3. 임베드: `#include "memtestG80_core.h"` → `allocate` → `gpuXxx` (LGPL 링크 조건)
4. 오류 센티넬(`0xFFFFFFFF`/`0xFFFFFFFE`)과 40억대 "오류"의 정체

**미니 프로젝트 (Capstone)**: (A) 체커보드 테스트 추가 · (B) 오류 비트 히스토그램 · (C) `--only` 플래그

**코드 리딩**: `memtestState`(`core.h:65`), `allocate`/`deallocate`(`core.cu:38`, `51`), `cli.cu`의 임베드 패턴

**실습 랩 (Lab 5)**: [`세션5_실습랩_캡스톤.md`](세션5_실습랩_캡스톤.md) — 최소 임베드 프로그램, allocate 실패 처리, 센티넬 체험, 캡스톤
