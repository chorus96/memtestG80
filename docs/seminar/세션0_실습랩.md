# 세션 0 실습 랩 — 환경 구축과 큰 그림

> **선행 조건**: NVIDIA CUDA 지원 GPU + CUDA Toolkit(nvcc), 또는 Google Colab(무료 GPU).
> **소요 시간**: 약 40분
> **작업 방식**: 각 실습(Exercise)은 **① 목표 → ② 명령/코드 → ③ 실행 → ④ 관찰 → ⑤ 생각해보기** 순서입니다.
> 한글 용어 옆의 (영어)는 원어 표기입니다.

---

## 준비 — 툴체인 확인

```bash
nvcc --version        # CUDA 컴파일러가 보이면 OK
nvidia-smi            # GPU와 드라이버가 인식되는지 확인
```

> `nvcc`가 없으면 CUDA Toolkit을 설치하거나 Google Colab(런타임 → 런타임 유형 변경 → GPU)에서 진행하세요.
> Colab에서는 `!nvcc --version`, `!nvidia-smi` 처럼 앞에 `!`를 붙입니다.

## Exercise 1 — MemtestG80 빌드하기

**① 목표**: OS별 Makefile로 `memtestG80` 실행 파일을 만든다.

**② 명령**:
```bash
# 저장소 루트에서 (본인 OS에 맞는 Makefile 선택)
make -f Makefiles/Makefile.linux64      # 64비트 리눅스
# 다른 OS: Makefile.linux32 / Makefile.osx / Makefile.windows
```

> 빌드 실패 시 대부분 `Makefiles/Makefile.linux64` 상단의 `CUDA_DIR` 경로 문제입니다.
> 본인 환경의 CUDA 라이브러리 위치(예: `/usr/local/cuda/lib64`)로 맞추세요.

**③ 실행**: 빌드가 끝나면 `memtestG80` 파일이 생깁니다.
```bash
ls -la memtestG80
```

**④ 관찰**: 빌드 로그에 `-Xptxas -v` 덕분에 커널별 **레지스터/공유 메모리 사용량**이 출력됩니다. 눈여겨 보세요(세션 3에서 다시 옵니다).

**⑤ 생각해보기**: 이 프로젝트는 CMake가 아니라 OS별 Makefile을 씁니다. 소스 파일이 단 몇 개뿐인 프로젝트에서 이 선택의 장단점은?

## Exercise 2 — 기본 실행

**① 목표**: 아무 인자 없이 실행해 기본 동작을 본다.

**② 명령**:
```bash
./memtestG80                 # 기본: GPU 0, 128MB, 50 iterations
```

**③ 실행**: 첫 줄에 대역폭 추정치가 나오고, 이어서 `Test iteration 1 ...`부터 반복이 시작됩니다.

**④ 관찰**: 출력의 구조를 파악하세요.
- 맨 위: `Estimated bandwidth ... MB/s` (세션 4에서 원리를 배웁니다)
- 각 iteration마다 **13종 테스트**가 순서대로 실행되고 각각 오류 수·소요 시간(ms)을 출력
- 맨 아래: `Final error count ...`

**⑤ 생각해보기**: 정상 GPU라면 오류 수가 0이어야 합니다. 만약 `Moving Inversions`에서 4,000,000,000이 넘는 숫자가 나온다면 무슨 뜻일까요? (힌트: 세션 5의 "오류 센티넬")

## Exercise 3 — GPU가 일하는 모습 관찰

**① 목표**: 테스트 중 GPU 사용률·메모리를 눈으로 확인한다.

**② 명령**: 터미널 두 개(또는 백그라운드 실행)를 씁니다.
```bash
# 터미널 A: 넉넉한 크기로 오래 실행
./memtestG80 512 200

# 터미널 B: 0.5초마다 GPU 상태 갱신
watch -n 0.5 nvidia-smi
```

**③ 실행**: 터미널 A가 도는 동안 터미널 B를 관찰합니다.

**④ 관찰**: `memtestG80` 프로세스의 **GPU 사용률(%)**과 **메모리 사용량(MiB)**을 확인. 512MB를 요청했는데 실제 사용량은 왜 그보다 클까요?(임시 버퍼)

**⑤ 생각해보기**: `nvidia-smi`의 사용률이 100%에 가깝게 유지되나요? 이것이 세션 1에서 배울 "52만 스레드 병렬성"의 결과입니다.

## Exercise 4 — 인자 실험

**① 목표**: 메모리 크기·반복 수가 실행 시간에 어떻게 영향을 주는지 체감한다.

**② 명령**:
```bash
time ./memtestG80 64 10
time ./memtestG80 128 10
time ./memtestG80 256 10
```

**③ 실행**: 각 명령의 `real` 시간을 기록합니다.

**④ 관찰**:

| 테스트 크기(MB) | 반복 수 | 실행 시간(real) |
|---:|---:|---|
| 64 | 10 | |
| 128 | 10 | |
| 256 | 10 | |

**⑤ 생각해보기**: 메모리를 2배로 늘리면 시간도 대략 2배가 되나요? 테스트는 데이터 양에 비례하는(선형) 작업임을 확인하세요. 실제 결함을 잡으려면 왜 "크게, 오래" 돌려야 할까요?
