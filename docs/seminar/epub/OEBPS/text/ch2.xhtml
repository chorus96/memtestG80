2. CUDA 실행 모델과 주소 매핑

2.1 커널과 실행 계층

CUDA에서 GPU 위에서 실행되는 함수를 커널(kernel)이라 부르며, __global__ 한정자로 표시합니다. 커널은 CPU(호스트, host)가 호출하고 GPU(디바이스, device)의 수많은 스레드가 동시에 실행합니다. 반환형은 항상 void이며, 결과는 인자로 받은 디바이스 포인터를 통해 메모리에 남깁니다.

커널을 실행하면 스레드는 3단 계층으로 조직됩니다. 큰 격자인 그리드(grid) 안에 블록(block)이 있고, 블록 안에 스레드(thread)가 있습니다. 각 스레드는 다음 내장 변수로 자기 위치를 압니다.

표 2. CUDA 내장 변수 (MemtestG80은 1차원 .x만 사용)
변수의미MemtestG80 값
blockIdx.x그리드 안에서 이 블록의 번호0 ~ 1023 (스레드마다 다름)
threadIdx.x블록 안에서 이 스레드의 번호0 ~ 511 (스레드마다 다름)
blockDim.x블록당 스레드 수512 (모두 같음)

메모리는 결국 1차원 주소 공간이므로, MemtestG80은 그리드·블록·스레드를 모두 1차원(.x)으로만 씁니다. 커널 실행은 삼중 꺾쇠 <<<nBlocks, nThreads>>>로 구성을 지정합니다.

2.2 THREAD_ADDRESS와 메모리 병합

이 도구의 심장은 단 한 줄의 매크로입니다. 모든 테스트 커널이 이 매크로로 자신이 건드릴 메모리 주소를 계산합니다.

네 개의 항이 각각 역할을 나눠 맡습니다.

  • base — 테스트 영역의 시작 주소.
  • blockIdx.x * N * blockDim.x — 이 블록이 담당하는 큰 구역의 시작. 블록마다 N × 512 word씩 널찍이 떨어져 서로 겹치지 않습니다.
  • i * blockDim.x — 블록 안에서 i번째 반복의 오프셋. 한 스레드가 총 N개의 word를 담당합니다.
  • threadIdx.x — 그 안에서 내 스레드의 위치(0~511).
왜 이렇게 매핑하는가 — 메모리 병합(coalescing)

핵심은 인터리빙입니다. 같은 반복 i에서 이웃한 스레드 (threadIdx.x가 인접한 스레드)는 이웃한 메모리 주소를 맡습니다. 덕분에 워프(warp, 32개 스레드)의 접근이 하나의 메모리 트랜잭션으로 묶이는 메모리 병합(coalescing)이 일어나 대역폭을 최대로 활용합니다. 만약 각 스레드가 큰 간격으로 흩어진 구간을 맡으면 트랜잭션이 쪼개져 느려집니다.

이 매크로가 인덱싱의 복잡함을 모두 흡수한 덕분에, 실제 커널 본문은 놀랍도록 단순해집니다. 가장 기본이 되는 쓰기 커널을 봅시다.

경계 검사가 없는 이유는, 테스트 영역이 항상 2·N MiB의 배수(1024 × 512 × N word)로 할당되어 그리드에 정확히 맞아떨어지기 때문입니다. 범위를 벗어나는 스레드가 존재하지 않으므로, 복잡함은 전부 THREAD_ADDRESS가 흡수하고 커널은 세 줄로 끝납니다.
