III. MemtestG80의 설계와 검증

이 절에서는 G80/Tesla 아키텍처 기반 NVIDIA GPU의 메모리 오류를 시험하는 CUDA 기반 코드인 MemtestG80의 설계와 검증을 기술한다. MemtestG80은 x86 기반 머신용으로 널리 쓰이는 오픈소스 메모리 테스터 Memtest86의 메모리 테스트 대부분을 CUDA로 구현한 것이다. Memtest86은 무작위 테스트와 패턴 민감 오류 테스트를 포함해 여러 대중적 메모리 테스트 패턴을 구현한다. VI-D절에서 MemtestG80이 구현한 테스트를 간략히 나열한다. 대부분의 테스트 패턴 설명은 간결성을 위해 Memtest86 문서로 대신하고, 여기서는 코드의 병렬 GPU 구현에서 내린 설계 결정을 중점적으로 다룬다. 또한 MemtestG80 고유의, 우리가 직접 고안한 로직 테스트의 구현도 상세히 설명한다.

이하 본문에서 MemtestG80의 한 "이터레이션(iteration)"은 구현된 각 테스트를 한 번씩 실행하는 것을 가리킨다. 여러 라운드로 진행되는 테스트의 경우 모든 라운드를 실행한다(한 가지 예외는 IV-A절에서 설명). 64 MiB 메모리에 대한 이런 이터레이션은 GPU 속도에 따라 보통 1~5초가 걸리며, 실행 시간은 시험한 메모리 양에 선형으로 비례한다.

III-A. 오프로드 및 병렬화 방식

소프트웨어 기반 GPU 메모리 테스터의 민감도와 속도에는 여러 설계 매개변수가 영향을 준다. 구체적으로 메모리 테스터의 세 구성 요소 — 패턴 생성, 메모리 접근(메모리에 패턴을 쓰고 읽기), 패턴 검증 — 은 CPU 또는 GPU 자체에서 수행될 수 있고, GPU에서 수행한다면 여러 GPU 코어에 걸쳐 직렬 또는 병렬로 수행될 수 있다. MemtestG80에서 내린 결정은 시스템 각 구성 요소의 상대적 오류율에 대한 우리의 가정과, 기증된 분산 컴퓨팅 자원 상에서 동작할 때 요구되는 응답성 요건에 근거한다.

테스터의 속도와 응답성을 높이기 위해, 모든 패턴 생성·메모리 접근·검증은 GPU에서 병렬로 수행된다. 우리는 메모리 오류율이 충분히 낮아, (시험 영역보다 훨씬 작은 공간을 차지하는) GPU 상의 코드가 테스트 실행 중 손상되지 않는다고 가정한다. 검증을 GPU에서 수행하면 테스터가 GPU 로직 오류에 취약해진다. 따라서 우리는 GPU 로직 오류율이 GPU 메모리 오류율보다 낮다고 암묵적으로 가정한다. 다만 이 가정은, 테스터의 다른 부분이 사용하는 것과 유사한 아키텍처 경로에서 오류를 보고해야 하는 맞춤형 로직 테스트를 함께 실행함으로써 검증한다.

III-B. 로직 테스트

GPU의 결과는 오직 GPU 주 메모리로부터의 복사를 통해서만 호스트 CPU로 전달될 수 있으므로, "메모리 오류가 로직 오류보다 빈번하다"는 가정 아래 GPU 로직 오류를 검출하기란 간단치 않다. 계산 결과의 오류가 로직 때문인지 메모리 때문인지 구별하기 어렵기 때문이다. 이 문제를 극복하기 위해, 로직 연산량을 달리해도 같은 기대 결과를 내는 테스트를 설계할 수 있다. 같은 테스트를 두 번 실행하되 두 번째 실행에서 (예컨대) 로직 연산을 4배로 한다. 두 테스트가 메모리에 같은 데이터를 쓰므로 메모리 결함에 의한 기대 오류율은 두 실행에서 동일하다. 반면 후자가 더 많은 로직 연산을 수행하므로, 로직 결함에 의한 오류는 연산 횟수에 비례해 증가해야 한다.

MemtestG80 고유의 로직 테스트 설계는 이 원리에 기반한다. 핵심 계산으로는 0에서 출발하는 짧은 주기 k의 선형 합동 난수 생성기(LCG)를 사용한다. 이런 생성기는 0에서 출발하면 고정된 반복 횟수 k 뒤에 다시 0으로 돌아온다. 생성기가 (32비트 생성기의 경우) 가능한 232 상태 중 오직 k개의 상태에만 도달하므로, 비트당 오류 확률이 균일하다고 가정하면 대부분의 로직 오류는 생성기를 정상 동작 주기 밖의 상태로 전이시킨다. 그런 상태는 올바른 단계 수 안에 0으로 돌아올 가능성이 낮으므로, 생성기가 0으로 되돌아오는지 여부가 로직 오류 발생 여부의 좋은 지표가 된다. 우리의 로직 테스트는 생성기를 0에서 시작해 k 또는 4k 사이클 동안 돌리고, 매번 결과를 메모리에 써서 되읽은 뒤 0만 담겨 있는지 검증한다. 0이 아닌 값은 로직 또는 메모리 오류의 존재를 뜻한다. 0이 아닌 값의 개수가 LCG 반복 횟수에 따라 증가한다면, 이는 메모리가 아니라 로직 오류를 가리킨다. 시험 패턴으로 상수 0을 쓰는 것은 이 테스트를 메모리 오류보다 로직 오류에 더 민감하게 만든다. III-C절에서 보이듯 상수 0 패턴은 결함 있는 메모리에 둔감하기 때문이다.

III-C. 검증(대조 실험)

MemtestG80을 검증하기 위해 음성 대조와 양성 대조 실험을 모두 수행했다. 본 연구의 목적이 GPU 하드웨어의 잠재 오류율을 조사하는 것이므로, 진정한 음성 대조(오류가 없음을 보장하는 대조)는 불가능하다. 과열이나 전력 교란에 의한 오류 가능성을 최소화하기 위해, 대조 실험은 온도가 통제된 환경에서 양호한 것으로 알려진 전원을 사용해 실행했다. 우주선 같은 주변 방사선에 대한 차폐는 수 미터의 콘크리트나 암석을 요하므로 비현실적이라 판단했다.

음성 대조는 두 종류의 하드웨어에서 실행했다. 첫째는 NVIDIA 기준 클럭으로 동작하는 고급 소비자용 그래픽 보드 GeForce 8800 GTX였다. 둘째로 8개의 NVIDIA Tesla C870 보드 클러스터에서 시험했다. Tesla C870은 GPGPU 전용으로 설계된 보드로, 8800GTX와 같은 GPU 아키텍처에 기반하며, NVIDIA가 "프로" 또는 GPGPU 등급 카드를 위해 가한 공학적 변경을 반영해야 한다. 8800GTX에서 700 MiB의 GPU 메모리에 대해 93,000회 이상의 MemtestG80 이터레이션을 실행했다. 각 Tesla 보드에서는 320 MiB에 대해 총 148만 회의 이터레이션을 실행했다. 음성 대조 8800GTX나 Tesla 보드에서는 오류가 전혀 검출되지 않았으며, 이는 MemtestG80이 검출하는 오류가 가짜이거나 코드 오류에 의한 것일 가능성이 낮음을 보여준다.

MemtestG80이 메모리 오류를 유발하는 것으로 알려진 조건에서 오류를 검출함을 확인하기 위해 양성 대조 실험도 수행했다. 오버클럭은 (메모리와 메모리 컨트롤러 회로 모두의 타이밍 제약 위반으로 인해) 메모리 오류를 유발하는 것으로 알려져 있으므로, 우리는 오버클럭을 양성 대조로 사용했다. GeForce 9500GT 비디오 카드(기본 메모리 클럭 400 MHz)에서 메모리 클럭을 400, 420, 430, 440, 450, 475, 500, 530 MHz로 설정해 MemtestG80을 실행했다. 각 시험은 20회 이터레이션(530MHz에서는 불안정으로 10회)으로 구성했다. 각 클럭 주파수 사이에는 보드를 400MHz로 재설정하고 일정 온도로 냉각시켜 열 효과가 결과에 영향을 주지 않게 했다. 마지막으로 400 MHz에서 20회를 추가 실행해, 중간의 오버클럭이 결과에 영향을 주지 않았음을 확인했다. 양성 대조 실험의 결과는 그림 1에 제시한다.

두 결과가 특별히 주목할 만하다. 첫째, 이동 반전 테스트의 두 변형(0, 전부 1, 또는 난수 상수를 시험 메모리의 모든 워드에 쓰고 되읽음)은 오버클럭에 의한 오류에 완전히 둔감하다. 이는 로직 테스트 패턴으로 전부-0 패턴을 선택하게 한 근거가 되는데, 이 패턴이 메모리 오류에 둔감해 보이기 때문이다.

둘째, 모듈로-20(modulo-20) 테스트가 다른 테스트보다 오버클럭 유발 오류에 훨씬 민감하며, 다른 테스트에서 오류를 유발하는 데 필요한 것보다 낮은 클럭 속도에서 오류를 검출하기 시작한다는 사실이 이를 보여준다. 모듈로-20 테스트는 20개 라운드로 진행된다. 라운드 i에서, 시험 메모리 시작점으로부터의 오프셋이 i를 20으로 나눈 나머지와 같은 각 메모리 위치에 32비트 패턴을 쓰고, 나머지 모든 메모리 위치에는 그 패턴의 비트 보수를 두 번 쓴다. 검증 커널에서는 오프셋이 i modulo 20인 위치를 되읽어 원래 패턴이 들어 있는지 확인한다. 이 절차를 i ∈ {0, 1, 2, ⋯, 19}에 대해 반복한다.

이 테스트의 민감성은, 테스트의 스트라이드 20이 메모리 칩의 어떤 아키텍처적 스트라이드(예: 행 길이나 칩 인터리브 계수)와도 정렬될 가능성이 낮다는 사실에서 비롯될 것이다. 그래서 시험 위치들이 물리적으로 흩어져 인접 셀의 영향을 받을 가능성이 커진다. 모듈로-20 테스트의 민감성은 실제 환경에서도 지속되며, 우리의 오류율 표본화에 핵심적이다. 메모리 서브시스템의 이 패턴 민감성 자체가 흥미로운 결과다. 메모리 오류를 마주칠 가능성이 접근 패턴과 데이터 패턴에 크게 의존함을 보여주기 때문이다.
