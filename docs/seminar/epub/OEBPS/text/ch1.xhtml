1. 왜 GPU 메모리를 검사하는가 · MemtestG80 개요

1.1 조용히 틀리는 하드웨어

현대의 그래픽 처리 장치(GPU, Graphics Processing Unit)는 수천 개의 코어로 대량의 데이터를 동시에 처리합니다. 그러나 소비자용 GPU 대부분은 오류 정정 코드(ECC, Error-Correcting Code)를 갖추고 있지 않습니다. 이는 메모리의 한 비트가 물리적으로 뒤집혀도 하드웨어가 이를 알아채지 못한 채, 잘못된 값이 그대로 계산에 섞여 들어갈 수 있음을 뜻합니다.

이런 오류는 크게 두 종류로 나뉩니다.

  • 하드 오류(hard error) — 항상 재현되는 물리적 결함입니다. 특정 셀이 항상 0 또는 1로 고정되거나(stuck-at), 인접 셀·데이터 라인이 단락되는 경우가 이에 해당합니다.
  • 소프트 오류(soft error) — 간헐적으로만 나타나는 오류입니다. 오버클럭, 발열, 전압 마진 부족, 심지어 우주선(cosmic ray)에 의한 비트 플립이 원인이 됩니다.
중요!

소프트 오류는 산발적이어서 잡기가 어렵습니다. MemtestG80의 문서는 "문제 있는 카드조차 5만 번에 한 번 꼴로만 실패할 수 있다"고 경고합니다. 따라서 안정성 검증은 본질적으로 스트레스 테스트이며, 가능한 큰 영역을 수천 번 반복해야 결함이 드러납니다.

1.2 CPU 테스터로는 부족하다

CPU의 주 메모리를 검사하는 Memtest86 같은 도구는 오래전부터 있었습니다. 그러나 GPU의 비디오 메모리(VRAM)는 CPU에서 직접 두드릴 수 없습니다. GPU 메모리를 검사하려면 GPU 위에서 직접 실행되는 테스터가 필요합니다. MemtestG80은 바로 이 목적을 위해, Memtest86의 검증된 메모리 테스트 알고리즘들을 CUDA 커널로 이식한 도구입니다.

1.3 MemtestG80이란

MemtestG80은 스탠퍼드 대학의 Folding@home 팀이 2009년에 공개한, NVIDIA CUDA 지원 GPU용 오픈소스 메모리·로직 테스터입니다. LGPL(GNU Lesser General Public License) v3로 배포되며, 폐쇄형 버전의 오픈소스 에디션에 해당합니다.

설계 의도 — 라이브러리 우선

MemtestG80의 주된 의도된 사용처는 라이브러리입니다. 다른 소프트웨어 개발자가 자신의 프로그램에 이 코드를 링크해, 연산을 실행하기 전에 GPU가 정상인지 검증할 수 있도록 설계되었습니다. 공개 API는 memtestG80_core.h에 정의되어 있습니다.
