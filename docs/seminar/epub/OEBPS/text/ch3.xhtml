3. 쓰기·검증과 병렬 리덕션

3.1 쓰기 → 검증 뼈대

모든 메모리 테스트는 하나의 단순한 뼈대 위에 서 있습니다. 알려진 패턴을 쓰고, 커널이 끝난 뒤, 되읽어 기대값과 비교합니다. 가장 고전적인 테스트인 이동 반전(Moving Inversions)이 이 뼈대를 전형적으로 보여줍니다.

왜 쓰기와 읽기를 나누는가

커널 실행은 비동기(asynchronous)입니다. 호스트는 커널을 띄운 뒤 곧바로 다음 줄로 갑니다. 따라서 되읽기 전에 반드시 GPU 완료를 기다려야 하며, 이 역할을 SOFTWAIT() 매크로가 합니다 (memtestG80_core.h:49). 커널 경계가 곧 메모리 배리어가 되어, 모든 스레드의 쓰기가 전역 메모리에 확실히 반영된 뒤에 검증이 시작됩니다. SOFTWAIT은 드라이버의 스핀 대기 대신 슬립하며 폴링하고, 15초 안에 끝나지 않으면 타임아웃 값 0xFFFFFFFE를 반환합니다.

3.2 __popc와 트리 리덕션

52만 개의 스레드가 각자 자기 word들을 검사해 오류 수를 셌다면, 이제 그 전체 합을 구해야 합니다. 모든 스레드가 하나의 전역 카운터를 동시에 늘리면 경쟁 조건(race condition)으로 값이 뭉개지고, 원자연산으로 직렬화하면 52만 번의 경합이 발생해 느립니다. MemtestG80은 계층적 리덕션으로 이를 해결합니다.

먼저, 오류를 세는 방식 자체가 영리합니다. 단순히 "맞다/틀리다"가 아니라, 뒤집힌 비트의 개수를 셉니다.

__popc는 하드웨어 인트린식(단일 명령)입니다. 한 word에서 여러 비트가 손상되어도 모두 포착되므로 오류율 추정이 정밀해집니다. 이렇게 스레드별로 센 부분합을, 블록 안에서 공유 메모리(shared memory)를 이용해 트리 형태로 접어 합칩니다.

stride를 512 → 256 → … → 1로 절반씩 줄이며, 각 단계마다 절반의 스레드만 이웃 값을 더합니다. 9단계(log₂ 512)면 512개가 하나로 접힙니다.

중요! __syncthreads의 역할

각 stride 단계는 이전 단계의 결과에 의존합니다. __syncthreads()는 블록 안 모든 스레드가 이 지점에 도달할 때까지 기다리는 배리어(barrier)로, 공유 메모리 쓰기가 서로에게 보이도록 보장합니다. 이 동기화를 빠뜨리면 일부 스레드가 앞서가 이웃의 옛 값을 더하게 되어, 정상 GPU인데도 합계가 실행마다 달라지는(비결정적) 버그가 생깁니다.

마지막 3단계는 호스트가 맡습니다. GPU는 52만 개를 블록당 1개, 즉 1024개로 줄이고, 그 1024개만 CPU로 복사해 최종 합산합니다.
