## 오늘의 주인공 코드

세션 1의 write 커널이, 이제 verify 커널과 짝을 이룹니다.

```c
// memtestG80_core.cu:370 — Moving Inversions (ones/zeros)
__host__ uint gpuMovingInversionsOnesZeros(...) {
    gpuWriteConstant (nBlocks,nThreads,base,N,0xFFFFFFFF);   // 전부 1을 쓴다
    SOFTWAIT();                                              // 커널 완료 대기
    errorCount  = gpuVerifyConstant(...,0xFFFFFFFF,...);     // 1이 유지되는지 검증

    gpuWriteConstant (nBlocks,nThreads,base,N,0x0);          // 보수(전부 0)로 덮는다
    SOFTWAIT();
    errorCount += gpuVerifyConstant(...,0x0,...);            // 0이 유지되는지 검증
    return errorCount;
}
```

**핵심**: 패턴을 쓰고 → **커널이 끝난 뒤**(메모리 반영) → 되읽어 비교 → 보수로 덮어 재검증.

## Exercise 1 — 패턴을 바꿔보기

**① 목표**: write/verify가 어떤 상수든 검증한다는 것을 확인한다.

**② 코드**: `gpuMovingInversionsOnesZeros`(core.cu:370)의 상수를 바꿉니다.

```c
    gpuWriteConstant(nBlocks,nThreads,base,N, 0xAAAAAAAA);   // 1010... 패턴
    SOFTWAIT();
    errorCount  = gpuVerifyConstant(nBlocks,nThreads,base,N, 0xAAAAAAAA, devTempMem, hostTempMem);
    gpuWriteConstant(nBlocks,nThreads,base,N, 0x55555555);   // 0101... 보수
    SOFTWAIT();
    errorCount += gpuVerifyConstant(nBlocks,nThreads,base,N, 0x55555555, devTempMem, hostTempMem);
```

> `0xAAAAAAAA`와 `0x55555555`는 서로 보수인 "체커보드" 패턴입니다.

**③ 실행**:
```bash
make -f Makefiles/Makefile.linux64
./memtestG80 64 1
```

**④ 관찰**: 정상 GPU라면 `Moving Inversions` 오류가 여전히 0인지 확인.

**⑤ 생각해보기**: 상수를 무엇으로 바꿔도 오류가 0이어야 정상입니다. 이 테스트가 실제로 검증하는 것은 "특정 값"이 아니라 무엇인가요?

> **끝나면 원복**: 원래의 `0xFFFFFFFF`/`0x0`으로.

## Exercise 2 — 오류를 인위로 주입 (검증기가 정말 잡나?)

**① 목표**: 검증 로직이 실제로 오류를 검출하는지 확인한다.

**② 코드**: `gpuMovingInversionsOnesZeros`에서 **쓰기와 검증 사이에** 메모리 한 칸을 일부러 훼손합니다.

```c
    gpuWriteConstant(nBlocks,nThreads,base,N,0xFFFFFFFF);
    SOFTWAIT();

    // === Exercise 2: 일부러 한 word를 틀리게 만든다 ===
    uint bad = 0xFFFFFFF7;                      // 1비트 뒤집힘
    cudaMemcpy(base, &bad, sizeof(uint), cudaMemcpyHostToDevice);
    // === 여기까지 ===

    errorCount = gpuVerifyConstant(nBlocks,nThreads,base,N,0xFFFFFFFF,devTempMem,hostTempMem);
```

**③ 실행**:
```bash
make -f Makefiles/Makefile.linux64
./memtestG80 64 1
```

**④ 관찰**: `Moving Inversions` 오류가 이제 **1**로 나오나요? (뒤집힌 비트 1개 → `__popc`가 1로 집계, 세션 3에서 원리를 배웁니다.)

**⑤ 생각해보기**: `0xFFFFFFF7`은 몇 비트가 틀렸나요? 두 비트를 뒤집으면(예: `0xFFFFFFF5`) 오류 수가 몇으로 나올지 예측하고 확인해 보세요.

> **반드시 원복**: 주입 코드를 지우세요.

## Exercise 3 — CPU 버전과 대조

**① 목표**: 같은 검증을 CPU로도 할 수 있음을 보고, GPU의 이점을 체감한다.

**② 코드**: `memtestG80_core.cu`에는 CPU 버전이 있습니다.

```c
// core.cu:241 cpuWriteConstant / core.cu:254 cpuVerifyConstant
// (3중 for 루프로 blockIdx/threadIdx/i를 CPU에서 흉내냄)
```

`gpuMovingInversionsOnesZeros` 안의 `gpuVerifyConstant` 한 곳을 `cpuVerifyConstant`로 바꿔봅니다.

```c
    // errorCount = gpuVerifyConstant(...);
    errorCount = cpuVerifyConstant(nBlocks, nThreads, base, N, 0xFFFFFFFF);
```

> ⚠️ CPU 함수는 `base`가 **디바이스 포인터**라서 그대로는 접근할 수 없습니다. 이 실습은 **컴파일해서
> 왜 잘못됐는지 토론**하는 데 목적이 있습니다(호스트/디바이스 메모리 구분).

**③ 실행/토론**: 빌드는 되지만 실행 시 잘못된 결과나 오류가 납니다.

**④ 관찰**: 왜 CPU 함수에 디바이스 포인터를 넘기면 안 되는가?

**⑤ 생각해보기**: GPU 검증은 52만 스레드가 동시에, CPU 검증은 한 코어가 순차로 합니다. 4GB를 검사할 때 시간 차이는 얼마나 될까요?

> **끝나면 원복**: `gpuVerifyConstant`로 되돌리세요.

## Exercise 4 — N(loopIters)의 정체

**① 목표**: 테스트 MB와 `N`의 관계를 확인한다.

**② 코드**: `memtestState::allocate`(core.cu:51)에 출력 한 줄을 추가합니다.

```c
    megsToTest = mbToTest;
    loopIters = megsToTest/2;
    printf("[HOST] megsToTest=%u, loopIters(N)=%u\n", megsToTest, loopIters);   // 추가
```

**③ 실행**:
```bash
make -f Makefiles/Makefile.linux64
./memtestG80 16 1
./memtestG80 64 1
```

**④ 관찰**: `N`이 `MB/2`인지 확인 (16MB→N=8, 64MB→N=32). 그리드 용량 공식 `2·N MiB = MB`와 일치하나요?

**⑤ 생각해보기**: 왜 `N = MB/2`일까요? 그리드가 `1024×512 word × N = 2·N MiB`를 덮는다는 세션 1 공식과 연결해 보세요.

> **끝나면 원복**: 추가한 `printf`를 지우세요.
