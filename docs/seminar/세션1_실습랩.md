## 오늘의 주인공 코드

이번 세션은 가장 단순한 커널 하나와 그것을 떠받치는 매크로를 중심으로 돕니다.

```c
// memtestG80_core.cu:26
#define THREAD_ADDRESS(base,N,i) \
    (base + blockIdx.x * N * blockDim.x + i * blockDim.x + threadIdx.x)

// memtestG80_core.cu:189
__global__ void deviceWriteConstant(uint* base, uint N, const uint constant) {
    for (uint i = 0; i < N; i++) {
        *(THREAD_ADDRESS(base, N, i)) = constant;   // 각 스레드가 자기 word들을 채움
    }
}
```

**읽는 법 (강사와 함께 한 줄씩)**
- `__global__` : 이 함수는 **커널(kernel)** — CPU가 호출하고 GPU가 실행.
- `blockIdx.x` : 지금 이 **블록(block)의 번호** (0 ~ 1023).
- `threadIdx.x` : 블록 안에서 이 **스레드(thread)의 번호** (0 ~ 511).
- `blockDim.x` : 블록당 스레드 수 = **512** (`memtestG80_core.h:78`).
- 이 커널은 `<<<1024, 512>>>`로 호출됩니다 — 블록 1024개 × 스레드 512개 = **524,288 스레드**.

호출하는 쪽:
```c
// memtestG80_core.cu:185
__host__ void gpuWriteConstant(const uint nBlocks,const uint nThreads,uint* base,uint N,const uint constant) {
    deviceWriteConstant<<<nBlocks,nThreads>>>(base,N,constant);
}
```

## Exercise 1 — 스레드는 자기가 누구인지 안다

**① 목표**: `blockIdx.x`·`threadIdx.x`가 스레드마다 다른 값이라는 것을 눈으로 확인한다.

**② 코드**: `deviceWriteConstant`(core.cu:189) 안에 디버그 출력을 추가합니다.

```c
__global__ void deviceWriteConstant(uint* base, uint N, const uint constant) {
    // === Exercise 1: 추가 ===
    if (blockIdx.x < 2 && threadIdx.x < 4) {          // 폭주 방지: 앞부분만
        printf("[GPU] blockIdx=%u threadIdx=%u addr=%p\n",
               blockIdx.x, threadIdx.x, (void*)THREAD_ADDRESS(base, N, 0));
    }
    // === 여기까지 ===
    for (uint i = 0; i < N; i++) {
        *(THREAD_ADDRESS(base, N, i)) = constant;
    }
}
```

> CUDA 커널 안에서도 `printf`가 됩니다(디바이스 printf, compute capability 2.0+). 단 수천 스레드가 동시에 찍으면
> 출력이 뒤섞이므로 조건으로 제한합니다.

**③ 실행**:
```bash
make -f Makefiles/Makefile.linux64
./memtestG80 2 1                 # 작게: 2MB, 1 iteration
```

**④ 관찰**: `blockIdx`가 0,1이고 각 블록의 `threadIdx` 0~3의 주소가 **4바이트씩** 연속인지 확인.

**⑤ 생각해보기**: 같은 블록에서 `threadIdx` 0과 1의 주소 차이는 몇 바이트인가? 왜 인접 스레드가 인접 주소를 맡는 것이 성능(coalescing)에 유리한가?

> **끝나면 원복**: 추가한 `printf` 블록을 지우세요.

## Exercise 2 — 블록의 구역은 어떻게 나뉘나

**① 목표**: `blockIdx.x`가 담당 구역을 어떻게 결정하는지 THREAD_ADDRESS로 확인한다.

**② 코드**: 이번엔 각 블록의 **첫 주소**만, 반복 i=0에서 출력합니다.

```c
    // deviceWriteConstant 맨 앞에 추가
    if (threadIdx.x == 0 && blockIdx.x < 4) {          // 각 블록의 0번 스레드만
        printf("[GPU] block %u 시작 addr=%p\n", blockIdx.x, (void*)THREAD_ADDRESS(base, N, 0));
    }
```

**③ 실행**:
```bash
make -f Makefiles/Makefile.linux64
./memtestG80 8 1                 # 8MB → N(loopIters)=4
```

**④ 관찰**: 블록 0,1,2,3의 시작 주소 간격을 계산하세요. 간격 = `N * blockDim.x * 4바이트` = `4 * 512 * 4` = **8192바이트**인지 확인.

**⑤ 생각해보기**: 블록들이 서로 겹치지 않는 자기 구역을 갖는 것이 왜 병렬 프로그래밍의 기본인가? (겹치면 어떤 문제가?)

## Exercise 3 — coalescing 깨보기 (사고 실험 + 코드)

**① 목표**: 인터리빙을 없애면 성능이 어떻게 변하는지 관찰한다.

**② 코드**: `THREAD_ADDRESS`의 인터리빙을 **일부러** 블록 단위로 바꿔봅니다. 커널 안에 대체 주소 계산을 넣습니다.

```c
    for (uint i = 0; i < N; i++) {
        // 원래: *(THREAD_ADDRESS(base, N, i)) = constant;
        // Exercise 3: 스레드가 연속 구간을 담당하도록 변경 (uncoalesced)
        uint idx = (blockIdx.x * blockDim.x + threadIdx.x) * N + i;
        base[idx] = constant;
    }
```

**③ 실행** (원래 버전과 시간 비교):
```bash
make -f Makefiles/Makefile.linux64
time ./memtestG80 256 20
```

**④ 관찰**: 원래 코드 대비 실행 시간이 어떻게 변했나요? (대개 느려집니다 — 접근이 흩어져 트랜잭션이 쪼개짐.)

**⑤ 생각해보기**: 두 방식 모두 "각 스레드가 N개 word를 쓴다"는 총량은 같습니다. 그런데 왜 속도가 다를까요? 메모리 병합(coalescing)의 의미를 자신의 말로 설명해 보세요.

> **반드시 원복**: 원래의 `THREAD_ADDRESS` 버전으로 되돌리세요.

## 마무리 — 자가 점검

- [ ] `__global__` 함수와 일반 함수의 차이를 한 문장으로 말할 수 있다.

- [ ] `THREAD_ADDRESS`의 네 항(base·block·i·thread)의 역할을 설명할 수 있다.
- [ ] "이웃 스레드 = 이웃 주소 → coalescing"의 의미를 안다.
